# XIAO ESP32-C6 + MAX30102：脈波・SpO₂・HRV を BLE で

> [English](README.md) | [中文](README.zh-CN.md) | 日本語

光学式脈波センサから読み取った生の光信号を Bluetooth で送るだけの、小さな心拍・SpO₂・HRV
モニター。残りはぜんぶ Web ページがやる。

作ったきっかけは単純で、チェストストラップを買わずに自分の心拍変動を眺めてみたかったから。
あと、数百円のセンサとブラウザだけでどこまでできるのか気になった。

## 考え方

デバイス側はあえて単純な作りにしてある。ESP32 は MAX30102 から生の IR/RED サンプルを
読み取り、100 Hz で BLE に流すだけ。フィルタも拍の検出もなしで、チップ上では一切計算しない。

その数字を意味のあるものに変える処理は、全部ブラウザ側の JavaScript でやる。拍の検出、拍
と拍の間隔、HRV、SpO₂、リアルタイムの波形。

こう分けた理由は二つ。

- C6 にはハードウェア FPU がない。整数より重い計算はソフトウェアエミュレーションになって
  遅いし、BLE スタックも同じシングルコアを奪い合うので、たまにメインループが止まるほどに
  なる。（これで一晩つぶした。いまはファームウェアを極力何もしない作りにしたら、症状は消
  えた。）
- アルゴリズムが Web ページにあると、変更はテキスト編集で済む。拍検出のパラメータをちょっ
  と動かすたびに書き込み直すのにうんざりした。いまは HTML を保存して再読み込みするだけ。

Chrome か Edge さえあれば Windows・macOS・Linux で同じように動くし、インストールするものは
何もない。

これは学習用で、医療機器ではない。MAX30102 が測るのは脈拍変動（PRV）で、安静時は心電由来
の HRV にそこそこ近いが、動くとずれる。絶対値はあまり真に受けないこと。

## ハードウェア

- Seeed XIAO ESP32-C6
- MAX30102 モジュール（よくある紫色の GY-MAX30102 で OK）
- ジャンパ線 4 本

配線（I²C）：

| MAX30102 | XIAO ESP32-C6 |
|----------|---------------|
| VIN      | 3V3           |
| GND      | GND           |
| SDA      | D4 (GPIO22)   |
| SCL      | D5 (GPIO23)   |

電源は 5V ではなく 3V3 から。センサの I²C アドレスは 0x57。スキャンして見つからないときは、
ほかを疑う前に、まずは SDA と SCL が入れ替わっていないか確認する。自分はこれだった。しかも
症状がいやらしくて、プルアップの電圧は正常、バスも健康そうに見えるのに、チップだけが応答
しない。

## ファームウェア

arduino-cli と Espressif の ESP32 core でビルドする。

```bash
arduino-cli config add board_manager.additional_urls \
  https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32
arduino-cli lib install "SparkFun MAX3010x Pulse and Proximity Sensor Library"

# コンパイルして書き込み。ポートは自分のものに置き換える
arduino-cli compile --fqbn esp32:esp32:XIAO_ESP32C6 -u \
  -p /dev/cu.usbmodemXXXX max30102_ble
```

MAX30102 は Red+IR、内部 400 Hz サンプリング・4 倍平均に設定してあり、実効 100 サンプル/秒
になる。ファームウェアはセンサの FIFO を吸い出して、小さなバッチにまとめて notify するだ
け。履歴も持たないし DSP もしない。ループを読むとほとんど退屈で、それが狙いどおり。

`XIAO-HR` という名前でアドバタイズする。USB シリアル 115200 で 1 秒ごとに 1 行（サンプル
レート、通し番号、直近の IR 値、ブラウザ側が接続しているか）を出すので、指を載せなくても
動いているか確認できる。

### BLE のフォーマット

サービス 1 つ、notify キャラクタリスティック 1 つ。各通知はリトルエンディアンのバイナリ
パケット：

```
[uint32 firstIndex][uint8 count][ count × (uint32 ir, uint32 red) ]
```

- `firstIndex` はそのパケット先頭サンプルの絶対番号。ブラウザはこれで時間軸を復元し、パ
  ケットが欠落したかどうかも検出する。
- `count` は現在 16 なので、通知は 1 秒あたり 6 回くらい。バッチを大きくすると通知が減って
  無線の負荷も下がる。それでいて、通常ネゴシエートされる MTU に収まる大きさ。
- サンプルレートは 100 Hz 固定で、ブラウザ側はこの値を決め打ちしてサンプル番号を時刻に変
  換する。

サービス `12345678-1234-5678-1234-56789abcdef0`、キャラクタリスティック `…def1`。

## Web アプリ

`web/index.html` は単一ファイルで、依存なし・ビルド不要・サーバ不要。ダブルクリックで開く。
Chrome か Edge を使うこと。Safari と Firefox は Web Bluetooth に対応していない。

接続して `XIAO-HR` を選び、指先をセンサの窓に当てて静止する。数秒で、拍ごとに点が付いた
脈波、心拍数、SpO₂、そして HRV パネルが出る。表示は日本語・英語・中国語に対応、パケット
をすべてログに残し、CSV 出力でき、回線が切れても自動で再接続する。

中で何をしているか：

- **拍の検出**：生の IR から、ゆっくりした指数移動平均（時定数およそ 2 秒）を引いてハイパ
  スフィルタをかける。これでベースラインのドリフトは消えるが脈は潰れない。この時定数を間
  違えると、まさに「何も検出できない」状態になる。残りを軽くローパスで平滑化し、減衰する
  包絡から作った適応しきい値でピークを探す。dicrotic notch（重複切痕）を 2 拍目と数えない
  よう、不応期も入れてある。
- **RR の計時**：検出した各ピークを前後 3 点の放物線フィットで補間し、10 ms のサンプル間隔
  より細かい分解能にする。RR は壁時計ではなくサンプル番号から計算するので、Bluetooth の
  ジッタでぶれない。
- **HRV**：時間領域のみ。平均 RR、RMSSD、pNN50、SDNN に、Poincaré 散布図の SD1/SD2。その前
  に、局所中央値から 30% 以上外れた間隔は捨てる。1 拍の取りこぼしや重複で数値が崩れないよ
  うに。
- **SpO₂**：おなじみの比の比、R = (AC_red/DC_red) / (AC_ir/DC_ir) を数秒の窓で求め、標準的
  な線形近似で SpO₂ に換算し、範囲内にクランプする。キャリブレーションはしていないので、目
  安として見ること。

拍検出のパラメータはスクリプト先頭のオブジェクト（`const P`）にまとまっている。すべてペー
ジ内にあるので、調整は編集して再読み込みするだけ。

```
max30102_xiao/   最初のシリアル専用版。参考用に残してある
```
